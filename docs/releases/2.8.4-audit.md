# 2.8.4 functional audit

**Compatibility fix: internal signing deferred; app and final setup remain signed.**

The audit found an update acceptance defect after signing Inno's internal
component: its higher internal file version and shared product name can make it
pass the existing update gate. The new 2.8.4 gate checks the executable's signed
FileDescription against the requested launch mode and rejects a renamed
uninstaller. Existing 2.8.1/2.8.3 clients still lack that check, so the final build
explicitly sets `SignedUninstaller=no`. They reject the unsigned internal component
at their existing signature gate. The final downloadable setup and bundled app
remain signed. Prior signing caches/evidence are cleared; publication requires
exactly one compiler signing artifact, byte-identical to the final installer.
An unexpected signed internal component blocks staging. This retains the internal
signing status of previous public releases and avoids exposing the unsafe artifact.

Independent read-only reviews covered native Windows API layouts, trust-state
and certificate lifetimes, publisher/timestamp binding, PE resource parsing,
startup cleanup, installer behavior and release signing. The compatibility fix was
independently checked against the old verifier and Inno 6.7.3 compiler source:
the outer setup is signed independently of the `SignedUninstaller` setting.

Verified compatibility and regression coverage:

- All 14 available historical/current signed installers and 11 signed app builds
  pass the native update gate in their proper launch mode when the client version
  is set lower for the test. An unsigned historical artifact remains rejected.
- An earlier local signed-uninstaller fixture was rejected in all launch modes.
  It is not part of the final release. Nine synthetic role/mode cases retain
  coverage, and release tests require explicit internal-signing disablement and
  reject absent, changed or additional compiler signing artifacts.
- Real signed fixtures cover signature and compressed-payload tampering, removed
  and forged timestamps, wrong publishers, downgrade rejection and file replacement.
  Signature verification creates no child process.
- Installer AppId, per-user destination, upgrade cleanup, optional finish launch,
  and silent update relaunch are unchanged. Startup cleanup still precedes both
  UI backends; it now runs once and preserves unrecognized files.
- Release signing was exercised with the actual Inno compiler and Azure signing
  helper. The exact verified outer-setup signing input is retained and compared
  before publishing; missing, changed or additional evidence blocks publication.
- The signed frozen self-check exercises the packaged native verifier. All seven
  changed Python modules and 45 packaged UI assets are compared against source.
  Client and backend suites cover the existing account, matchmaking and game flows.

Limits: no installer was executed on the affected player's PC, and no Avast or
Malwarebytes clearance is claimed. The reported Malwarebytes scan does not list
2.8.4; that is not evidence it passes. An end-to-end installation/upgrade/uninstallation in an
isolated Windows environment was not performed. Signing evidence verifies compiler
input rather than a post-install `unins000.exe`.
The PE parser deliberately accepts the existing single-resource/single-language
version layout; a future packaging change must preserve it or update the verifier.

## Final local verification

- Final setup: 24,205,032 bytes; SHA256 `8484faa781746de0b66fc1cb21c3950eab3e55a8bb80cb726ee3c3218dea8e57`.
- Historical 2.8.1 and 2.8.3 verifiers accept this exact signed setup; the new native verifier accepts it too.
- Private Python: 925 passed, three skipped, 26 subtests. Public Python: 917 passed, nine skipped, 26 subtests. Skips cover absent signed fixture artifacts. Both full backend suites exited successfully, including all 89 account checks.
- Signed frozen self-check passed; seven changed frozen modules and 45 UI assets match source. Compiler evidence contains only the final setup, byte-identical to the staged file.
- A scan of all 792 packaged Python modules found no PowerShell command references. The only `.ps1` string matches are standard-library documentation for Python's `sys.ps1` prompt. No `.ps1`, `.psm1`, `.bat`, `.cmd` or `.vbs` files are bundled. Reviewed process-launch sites use the game, Steam, scoped app helpers, Windows process utilities, verified update setup or the Inno uninstaller. Release-signing PowerShell runs only on the build PC and is not bundled.
- Read-only API/security, installer and public-source privacy reviews completed. No private source history, account IDs, credentials or private assets were added to the public diff.

These are static, unit/integration and frozen-build checks, not a complete
antivirus-monitored app session or isolated Windows installation test. No Avast
clearance is claimed.
